* 布局与权限

- =hosts/lappie/*.yaml=：管理员，以及未来的 lappie age key。
- =hosts/storie/*.yaml=：管理员，以及未来的 storie age key。
- =shared/*.yaml=：目前仅管理员；共享时为具体文件添加参与机器的规则。
- =keys/hosts/<hostname>.age.pub=：未来登记各机器的 age 公钥。

SOPS 权限边界是文件：能解密某个文件，就能读取其中全部内容。
不同机器的专属 secrets 必须分文件。新增主机必须显式添加路径规则；
没有匹配规则的路径不会默认获得任何 recipient。

* 编辑与验证

在仓库根目录操作。SOPS 已在 =env/guix/manifest.scm= 中声明，进入
项目的 direnv / Guix shell 环境后使用 =sops=。

#+begin_src sh
gpg --import secrets/keys/admin.asc
gpg --card-status
sops secrets/hosts/lappie/system.yaml
#+end_src

编辑器退出后 SOPS 保存密文。不要把私钥或明文文件提交到仓库。
=hosts/lappie/check.yaml= 是无敏感信息的加解密检查文件，未被系统服务引用：

#+begin_src sh
sops decrypt --extract '["check"]' secrets/hosts/lappie/check.yaml
#+end_src

预期输出 =uraj-sops-card-check-v1=。该文件有三个 recipient，解密成功
只证明至少一个可用；要分别验证子钥，需要每次仅以一个 recipient
创建测试密文，并在对应卡或私钥环境中解密。

* 后续接入机器

每台机器本地生成独立 age identity，计划保存于
=/var/lib/sops/age/keys.txt=（root 所有，目录 0700，文件 0600）。
已有 identity 必须保留，不能在每次 reconfigure 时重新生成。
只把公钥登记到 =keys/hosts/=，并在对应主机的 creation rule 中增加
=age: age1...=；保留 =pgp: *admin=，两者任意一个即可解密。

更新规则不会自动改变已有密文。持有管理员私钥时，逐个更新相关文件：

#+begin_src sh
sops updatekeys secrets/hosts/lappie/check.yaml
sops updatekeys secrets/hosts/lappie/system.yaml
#+end_src

仅对实际存在的文件执行，然后检查密文中的 recipients。
共享文件为每个用途单独创建规则，放在 shared fallback 之前，明确列出
获准机器；不会把所有机器的公钥加入每一个文件。

Guix 运行时集成计划使用 =(uraj system secrets)= 封装 sops-guix，
构建时只导入密文，启动时使用本机 age identity 解密到 =/run/secrets/=。
消费服务应声明解密依赖以及适当的 owner/group/mode。
私钥和明文均不得通过 =local-file= 等方式进入 Guix store。

机器重装或丢失 age identity 后，生成新 identity，由管理员更新 recipients。
移除泄露的 recipient 不会撤销其对旧 Git 历史密文的解密能力；若涉及泄露，
还需要更换相关业务凭据并轮换 SOPS 数据密钥。
