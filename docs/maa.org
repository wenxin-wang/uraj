#+title: Arknights automation

* Deployment with redroid

** Design

The hypie deployment template runs =redroid-maa= under Docker; its imports
and service block currently remain commented out pending deployment.  Guix
declares the container and its dependencies; Shepherd manages its lifecycle.
Android's =/data= is bind-mounted from =/var/lib/redroid/data/maa= on the
system disk.  Other Android instances must have separate names, data
directories and IP addresses.  Guix generation rollback does not roll back
Android data: stop the instance and back up its data before image upgrades.

Use the Intel HD 630 for rendering, not the GTX 1080.  Resolve the Intel
render device by PCI identity rather than assuming =renderD128=.  The host
kernel must support Binder; use memfd instead of the removed ashmem driver.

** Networking

Initial addressing (checked against all current IPv4 routing tables on start):

| Object      | Value           |
|-------------+-----------------|
| Docker net  | redroid         |
| Host bridge | br-redroid      |
| Subnet      | 10.203.0.0/24    |
| Gateway     | 10.203.0.1      |
| redroid-maa | 10.203.0.2:5555 |

These are defaults in =(uraj services redroid)=.  If a LAN or VPN overlaps,
change the network's subnet/gateway and the instance address together.

Use a dedicated Docker bridge with an independent network namespace for
Android.  Do not use host networking: Android manages routes and networking
inside its namespace, and its ADB daemon must not listen on the host's LAN
interfaces.  Do not publish container ports.

Guix's shared [[file:restricted-network.org][restricted-network service]] owns IPv4 forwarding and
nftables tables for egress masquerading and filtering.  Docker's automatic
iptables/ip6tables, IP forwarding and userland proxy management are disabled.
The default Docker bridge is disabled; the redroid network is explicitly
provisioned.  Rules must not flush or replace unrelated host/VPN rules.
Unsolicited forwarding into redroid is blocked; the host can connect
directly to the instance's private IP.  The private subnet must not overlap
the host's LAN or VPN routes.  Wi-Fi and Ethernet use the same routed design.

Only =inet restricted_network= and =ip restricted_network= are replaced,
atomically.  Stopping the network services retains protection; it never
deletes other instances' network.  Unrelated firewall tables are retained.
An existing host firewall can still reject forwarding: its policy must also
permit the intended traffic.  Containers may initiate public TCP/UDP
connections, but cannot access LAN/VPN/private destinations or host services.
DNS on TCP/UDP 53 is restricted to the configured resolver.  Host-started
ADB connections and their replies are allowed.  Containers on the same bridge
are not isolated from one another at layer 2; only trusted Android instances
should share it.

The =network= field of =redroid-configuration= holds a =restricted-network=
record, defaulting to =%redroid-network=.  The redroid service contributes
this record directly to =restricted-network-service-type=; no separate
redroid network service or field-conversion layer is needed.

#+begin_src scheme
(service restricted-network-service-type)
(service redroid-service-type
  (redroid-configuration
    (network
     (restricted-network
       (inherit %redroid-network)
       (egress-interfaces #t)))
    (auto-start? #f)))
#+end_src

Set the embedded network's =egress-interfaces= to =#t= or the actual uplink
list; the empty default permits no new outbound traffic.  Public LAN/VPN
prefixes and public addresses that hairpin to private services must be added
to the policy's =blocked-destinations=.  The container network name comes
from the same record.  Docker's =--dns= options and Android's numbered DNS
boot arguments both use its policy's =dns-servers= list, which defaults to
='("114.114.114.114")=.  Redroid requires an explicit nonempty IPv4 list: =host=
snapshots are unavailable when its Android boot arguments are generated.
Egress follows the host's forwarding/routing policy; host-only proxy settings
are not automatically used by Android.  Split-tunnel VPN behavior needs
device testing.

** Control plane

=maa-cli=, MaaCore and adb run outside Android, eventually under a separate
scheduled job at 05:00, 14:00 and 21:00 Asia/Shanghai.  They connect to the
private Android IP on port 5555.  Initially validate Android boot, Intel
rendering, scrcpy, game installation and manual login before enabling MAA.
Changing the controller to mower later does not require replacing Android
or its persistent data.

** Implementation and first deployment

- =src/guix/uraj/services/redroid.scm=: Docker settings, public-only network
  policy contribution and Android instance service using Guix's OCI service.
- =src/guix/uraj/build/redroid.scm=: Android runtime checks.
- =env/guix/os/hypie.scm=: opt-in deployment block, still disabled.  Enable
  its imports, base =restricted-network-service-type= and redroid services
  together, and configure permitted egress before starting the instance.

The container initially has =(auto-start? #f)=.  Docker and network services
start at boot, but Android starts only on =herd start redroid-maa=.  After
validation, change this field to =#t= in hypie's instance declaration.
Shepherd restarts a failed container; there is no Docker restart policy that
could bypass the firewall/readiness dependencies.  A live container process
does not itself prove Android or the game is healthy.

The initial image is =docker.io/redroid/redroid:11.0.0-latest=.  This is a
bootstrap tag, not an immutable lock.  After successful testing, obtain its
RepoDigest and set the =image= field to that digest before treating deployment
as reproducible.  Do not upgrade Android versions against the same data
directory without a stopped-container backup and a tested recovery path.

Before reconfiguration, on hypie:

#+begin_src sh
grep binder /proc/filesystems
ls -l /dev/dri/by-path/pci-0000:00:02.0-render
ip -4 route show table all
#+end_src

The pinned Guix x86_64 kernel configurations include Binder and binderfs.
The running kernel still needs checking.  If binderfs is missing, load
=binder_linux= if it is a module, or rebuild/boot a kernel with Binder enabled.
No extra Binder DKMS module or ashmem driver is installed by this service.

The Intel device is bind-mounted at =/dev/dri/intel-render= inside Android.
The container is privileged, as in the upstream deployment recipe.  A
small statically linked entrypoint first bind-mounts =/proc/sys/kernel/modprobe=
read-only inside the container, then executes =/init androidboot.hardware=redroid ...=.
If that protection fails, Android is not started.  This avoids both Android
disabling host module autoloading (upstream [[https://github.com/remote-android/redroid-doc/issues/932][issue #932]]) and runc's rejection
of OCI mounts at that =/proc= path.  Its behavior still needs runtime validation
against the selected Android image.
The helper is built from =src/guix/uraj/packages/aux-files/redroid-init.c=.
It avoids depending on Android's shell/APEX libraries before init has run.

From the repository on hypie, with =TO_ISO= unset:

#+begin_src sh
sudo guix time-machine -C env/guix/channels-lock.scm -- \
  system -L src/guix -L src/guile reconfigure env/guix/os/hypie.scm
sudo herd start redroid-maa
sudo herd status redroid-maa
sudo docker logs --tail 100 redroid-maa
sudo docker network inspect redroid
sudo nft list table inet restricted_network
sudo nft list table ip restricted_network
#+end_src

Install/use =adb= and =scrcpy= as client-side tools; no Android controller
is installed by this first deployment:

#+begin_src sh
guix shell adb scrcpy
adb connect 10.203.0.2:5555
adb -s 10.203.0.2:5555 shell getprop sys.boot_completed
adb -s 10.203.0.2:5555 shell dumpsys SurfaceFlinger
scrcpy -s 10.203.0.2:5555
adb -s 10.203.0.2:5555 install /path/to/arknights.apk
#+end_src

Require boot completion =1=, Intel/Mesa hardware rendering rather than a
software renderer, working DNS and game login, and intact host networking.
Check the running container's read-only modprobe mount and compare the host
=/proc/sys/kernel/modprobe= before/after starting it.  Then record the image:

#+begin_src sh
sudo docker image inspect docker.io/redroid/redroid:11.0.0-latest \
  --format '{{json .RepoDigests}}'
#+end_src

For remote scrcpy, tunnel ADB through SSH instead of exposing it on the LAN:

#+begin_src sh
ssh -N -L 15555:10.203.0.2:5555 USER@HYPIE
# In another local terminal:
adb connect 127.0.0.1:15555
scrcpy -s 127.0.0.1:15555
#+end_src

** Validation status

The network implementation now uses the shared restricted-network service;
see [[file:restricted-network.org][its tests and migration instructions]].  The following records describe
the earlier redroid-specific implementation and are historical, not proof of
the new policy's deployment on hypie.

The service graph and subnet/network drift checks have automated tests:

#+begin_src sh
guix repl -L src/guix -L src/guile test/guix/uraj/services/redroid.scm
#+end_src

The nftables rules were also loaded twice in an isolated user/network
namespace: syntax and repeated application passed, and an unrelated table
survived.  This does not yet verify forwarding packets or Android networking.
The static entrypoint compiled with warnings treated as errors.  In an
isolated user/mount namespace it successfully bind-mounted the modprobe
sysctl read-only (confirmed in mountinfo) and reached =exec /init=; the test
namespace intentionally has no Android init.  It preserves procfs mount
safety flags.  The Scheme suite now has 25 passing checks.
System build and real-device boot/game validation remain pending; the coding
environment has no usable local Guix daemon socket.  No reconfiguration has
been applied to hypie.
