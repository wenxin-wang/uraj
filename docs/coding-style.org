* Coding style

C/C++ uses the applicable rules of the [[https://google.github.io/styleguide/cppguide.html][Google C++ style guide]], with
clang-format's Google preset and cpplint. Python uses the [[https://google.github.io/styleguide/pyguide.html][Google Python style guide]],
with Ruff for formatting and linting, configured in =ruff.toml=.
Ruff covers only part of the guide; review language usage and design too.
CPPLINT.cfg leaves whitespace to clang-format and permits C casts.

Python formatting uses 80 columns, four-space indentation and double quotes.
Lint enables =E4/E7/E9= (basic style/errors), =F= (undefined/unused names),
=I= (import sorting), =N= (naming), =D= (Google docstrings), and =B= (bug patterns).
Imports use one import per line and alphabetical ordering within sections.
Docstrings are optional throughout the repository: =D100-D107= are disabled.
Existing docstrings are still checked against the Google convention.
We do not enable =E501=: the formatter's line length is best-effort, and some
strings or comments cannot sensibly be wrapped. No Python minimum version is
imposed here; version-dependent modernization rules are not enabled.
This is not a complete replacement for Pylint's analysis or the Google guide.
See [[https://docs.astral.sh/ruff/formatter/][Ruff formatter]] and [[https://docs.astral.sh/ruff/settings/#lintpydocstyle_convention][Google docstring convention]].

=basic-dev= provides the tools. For a temporary environment:

#+begin_src sh
guix shell python clang cpplint ruff
scripts/coding_style/install-hooks
scripts/coding_style/check --staged
#+end_src

The pre-commit hook checks changed C/C++ and Python files from a temporary
snapshot of the index, including on the first commit. It never formats, stashes,
or stages files. Missing tools and violations block the commit with instructions.
Existing hooks are preserved: the installer reports any integration needed.
Each clone needs the installer once; no global Git configuration is changed.

#+begin_src sh
scripts/coding_style/check                 # all tracked sources, except vendor/
scripts/coding_style/check path/to/file.py # explicit working-tree files
scripts/coding_style/format path/to/file.py
scripts/coding_style/lint path/to/file.py  # diagnostics, no fixes
scripts/coding_style/fix path/to/file.py   # apply safe Ruff lint fixes
scripts/coding_style/fix                  # all tracked Python files, except vendor/
# Optional: explicitly fix import ordering reported as I001.
ruff check --select I --fix path/to/file.py
git diff                                 # review before staging
git add -p
scripts/coding_style/check --staged
#+end_src

Explicit paths may name new files; default scans only include tracked files.
Formatting changes working-tree files only. Review unstaged edits before
formatting or fixing a partially staged file. The =fix= command runs
=ruff check --fix --no-unsafe-fixes= on working-tree Python files only, without
staging them or formatting them. It rejects =--staged= and explicit non-Python
paths. Remaining diagnostics cause a nonzero exit even if some fixes succeeded;
review the diff, fix remaining findings manually, then format and restage.
The hook uses staged configuration when available, otherwise the working-tree
configuration during initial setup. Ruff checks explicitly use =--no-fix= and
=--no-cache=; formatting only runs =ruff format= and does not fix imports or lint.
Emacs uses the same project configuration, running Apheleia's =ruff-isort= then
=ruff= on save to sort imports and format Python buffers. Commit checks remain
read-only.
